# Open Source at Diseino

DiseinoCommunity is the public home for open-source work and community participation associated with Diseino Technologies. The initiative is new, and its portfolio is still to be developed.

## Why participate

Useful software and technical knowledge can help people beyond the organization that first built them. Diseino wants to make some work available for others to use, inspect, adapt, and improve, while learning from the wider ecosystem.

Participation includes contributing to existing open-source projects. Creating new repositories is not the only way to contribute; Diseino intends to make useful, well-scoped contributions to work maintained by others.

## What may be published

Possible areas include developer utilities, AI experiments and integrations, automation, reusable libraries, educational resources, documentation, and community-driven software. These are intentions, not claims that projects already exist.

## Open source and proprietary products

Diseino may build commercial proprietary products alongside open-source projects. These are distinct bodies of work. A product's code, architecture, documentation, and assets are not open source unless explicitly published under a stated licence.

CineSense and DiseinoPresenter are current working names for proprietary product initiatives. This repository grants no rights to their code or materials. Names may change as development continues.

## Meaningful contributions

The aim is to publish work that solves a real problem, has a clear scope, and can be maintained responsibly. Diseino values usefulness, clarity, and follow-through over repository counts or stars. A small, dependable contribution can be more valuable than a broad project that is abandoned.

## Licensing

This initial repository uses MIT for its own contents. Future projects may use other suitable licences. Each project must state its licence and respect the licences of third-party code, models, data, and assets. Check applicable permissions and obligations before publishing third-party material.

## Documentation and maintenance

Published projects should explain what they do, how to use or build them, their current status, and where to report issues. Public availability is not a promise of indefinite support. Communicate when a project is no longer actively maintained.

## Contributions

External contributions are welcome where scope and capacity allow. Maintainers will review fit, clarity, quality, licensing, and support needs. See [Contributing](../CONTRIBUTING.md). Projects may add their own guidance.
